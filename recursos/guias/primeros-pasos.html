Del cero a tu primer proyecto

Si nunca has programado o te pierdes con los términos técnicos, esta guía es para ti. Sin dar nada por sentado: qué instalar, qué es cada cosa, cómo proteger tus llaves y cómo no perder tu trabajo.

1Lo que necesitas

Tus tres herramientas básicas

Un navegador

Chrome, Edge o el que uses. Para ver tu sitio y abrir las guías. Ya lo tienes.

Un editor de código

VS Code es el más común y gratis. Es como Word, pero para código: ahí escribes y organizas tus archivos.

Node.js

El motor que hace correr proyectos web modernos. Trae npm, que instala piezas hechas por otros. Descárgalo de nodejs.org.

¿Qué es npm?

Piensa en npm como una tienda gigante y gratuita de piezas ya armadas. En vez de construir todo desde cero, escribes npm install y traes la pieza que necesitas (por ejemplo, orwel).

2La terminal, sin miedo

Esa "pantalla negra" es tu amiga

En palabras simples

La terminal es una forma de darle órdenes a la computadora escribiendo, en vez de hacer clic. Escribes un comando, presionas Enter, y pasa algo. No vas a romper nada por escribir un comando.

ComandoQué hace
cd mi-carpeta"Entrar" a una carpeta (change directory).
ls (o dir en Windows)Ver qué archivos hay donde estás.
npm installInstalar las piezas que el proyecto necesita.
npm run devEncender el proyecto en tu compu para verlo en el navegador.

Terminal de práctica

Escribe un comando y presiona Enter. Prueba: ls, cd src, npm install, git status, help.

Escribe un comando abajo y presiona Enter.

Tip

En VS Code abres una terminal integrada desde el menú Terminal → Nueva terminal. Queda apuntando a tu proyecto automáticamente.

3Anatomía de un proyecto

¿Qué es cada archivo y carpeta?

Cuando abres un proyecto te encuentras muchos archivos. La mayoría no los tocas. Estos son los que importan:

mi-proyecto/ ├── src/ # tu código vive aquí (lo que tú escribes) ├── node_modules/ # las piezas de npm. NO se toca, NO se sube ├── skills/ # las skills para tu asistente de IA ├── package.json # la "ficha" del proyecto: nombre y piezas que usa ├── .env # tus llaves secretas (NUNCA se sube) ├── .env.example # plantilla de qué llaves se necesitan (sí se sube) └── .gitignore # lista de lo que Git debe ignorar
  • src/ — tu trabajo. Aquí editas páginas y componentes.
  • node_modules/ — se crea solo al hacer npm install. Pesa mucho; jamás se sube ni se edita.
  • package.json — dice qué piezas usa el proyecto y qué comandos tiene (mira la sección "scripts").
  • .env — guarda tus secretos (como la API key de Orwel). Más sobre esto abajo.

4Variables de entorno (.env)

Dónde guardar tus llaves secretas

En palabras simples

Una "variable de entorno" es un dato secreto que tu proyecto necesita pero que no debe estar a la vista en el código, como una contraseña. El archivo .env es la cajita donde guardas esos secretos, separados del código que todos pueden ver.

Un .env es solo una lista de NOMBRE=valor, una por línea:

.env
VITE_ORWEL_KEY=orwel_tu_llave_secreta_aqui
OTRA_LLAVE=valor123

Y en el código la lees por su nombre, sin escribir el valor real:

en tu código
const apiKey = import.meta.env.VITE_ORWEL_KEY;  // lee del .env

Por qué tanto cuidado

Si subes tu API key a internet, cualquiera puede usarla y gastar tu cuota o ensuciar tus datos. Por eso el .env se mantiene solo en tu computadora.

El .env.example es una copia sin los valores reales, solo los nombres. Esa sí se sube, para que tus compañeros sepan qué llaves hace falta conseguir.

5Proteger tus secretos

Cómo NO publicar tus llaves por accidente

El error más común (y peligroso) de principiantes: subir el .env a internet sin querer. Aquí está cómo evitarlo.

El archivo .gitignore

Es una lista de archivos que Git debe ignorar — nunca subirlos. Asegúrate de que incluya .env y node_modules:

.gitignore
node_modules
.env
.env.local
dist

Si ya publicaste una llave

Considérala "quemada". Ve al sitio que la emitió (ej. orwel.io), bórrala y genera una nueva (esto se llama "rotar" la llave). Quitarla del código no basta: ya quedó en el historial.

Regla de oro

Antes de subir tu trabajo, pregúntate: "¿hay alguna contraseña o llave en estos archivos?". Si la respuesta es sí, debe estar en .env y el .env en .gitignore.

6Git en cinco minutos

Para no perder tu trabajo

En palabras simples

Git es como los "puntos de guardado" de un videojuego. Cada vez que avanzas algo, guardas un punto (un "commit"). Si algo se rompe, vuelves a un punto anterior. Y permite que varias personas trabajen sin pisarse. GitHub es la nube donde guardas esos puntos.

Guardar un punto y subirlo
git add .                          # prepara todos los cambios
git commit -m "Agregué el formulario"   # guarda el punto, con una nota
git push                           # súbelo a la nube (GitHub)
ComandoQué hace
git statusVer qué cambiaste desde el último punto.
git add .Marcar todos los cambios para guardar.
git commit -m "nota"Crear el punto de guardado con una descripción.
git pushSubir tus puntos a GitHub.
git pullBajar los cambios que subió un compañero.

Ramas (branches), el siguiente nivel

Una rama es una línea de trabajo paralela. Creas una con git checkout -b mi-rama para experimentar sin romper lo que funciona. Cuando queda bien, se une (merge) a la principal. En equipo, cada quien trabaja en su rama.

7Las skills

Dónde van y cómo se cargan

En palabras simples

Una skill es un instructivo que le das a tu asistente de IA para que haga algo bien y a nuestra manera. Es una carpeta con un archivo SKILL.md adentro. Tú no la "ejecutas": el asistente la detecta sola y la usa cuando hace falta.

Para instalar el pack, copia las carpetas de skills en tu proyecto, dentro de la carpeta que use tu asistente. Por ejemplo, en Claude Code es .claude/skills/; otros asistentes (Gemini, Cursor…) usan su propia convención.

mi-proyecto/ └── .claude/ └── skills/ ├── orwel/ │ └── SKILL.md # cada skill = una carpeta con su SKILL.md ├── hyper-llm/ │ └── SKILL.md └── hyper-doc/ └── SKILL.md
  • Cada skill vive en su propia carpeta, con su SKILL.md.
  • El asistente lee la descripción de cada skill y la activa cuando tu tarea coincide. No tienes que invocarla a mano.
  • Instala solo las que te sirvan; no estorban las demás.

Más detalle

Para conocer cada skill (qué resuelve, cuándo se activa, ejemplos), abre el Catálogo de Skills.

Lista para empezar

  • Tengo VS Code y Node.js instalados.
  • Sé abrir la terminal y entrar a mi carpeta con cd.
  • Mis llaves están en .env y .env está en .gitignore.
  • Hago git commit seguido para no perder mi avance.
  • Copié las skills que necesito a la carpeta de mi asistente.

Para el hackathon

Haz un git commit cada vez que algo funcione, no al final. Si algo se rompe a media demo, vuelves al último punto que servía en segundos — y te ahorras el infarto.
